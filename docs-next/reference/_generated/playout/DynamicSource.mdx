A placeholder source resolved at playback time by fetching a `PlayoutItem` JSON document over HTTP(S). The request and response are part of the playout schema: a change to either bumps its version, and the channel sends the version it implements in `x-etv-playout-schema`.

The request is a `GET` of `uri`, with `headers` and `user_agent`; redirects are followed. The channel adds these headers, replacing any configured header of the same name. Timestamps are RFC 3339, may include fractional seconds and may carry any UTC offset.

- `x-etv-channel` — the channel number.
- `x-etv-dynamic-id` — this placeholder's `id`. It is the same on every request within the placeholder's window, so resolvers can use it to coalesce or cache decisions.
- `x-etv-now` — the schedule position to fill. It is the channel's transcode position, which runs ahead of the wall clock while the channel works ahead.
- `x-etv-until` — the placeholder's `finish`.
- `x-etv-playout-schema` — the newest playout schema version this channel accepts, e.g. `https://ersatztv.org/playout/version/0.0.8`.

The response is a 2xx status with a JSON `PlayoutItem` body; the content type isn't checked and unknown fields are ignored. The item's `start` is moved to `x-etv-now`, keeping its duration, and its `finish` is clamped to `x-etv-until`. An item with no time left after that is refused, as is one with a `dynamic` source anywhere (main source, tracks, watermark or graphics). An invalid `probe_hint` is dropped with a warning and the item plays without it, as in a playout file; any other invalid item is refused. A refused or failed resolution plays the channel's fallback (see `retry_budget_ms` for what is retried).

When the resolved item finishes before the placeholder does, the channel requests again with the new `x-etv-now`, so one placeholder can return a sequence of items. The returned `id` identifies the content: an equal `id` reuses the previous item's converted subtitles and copy position, and after a source ends early, a response with the same `id` plays fallback instead. Return a distinct `id` for each distinct item.
